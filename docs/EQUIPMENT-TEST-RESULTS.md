## Конкурентность: 17 сценариев на PostgreSQL 18.4

Для каждой из 12 основных гонок тест удерживает первую транзакцию открытой, запускает вторую, наблюдает ожидание блокировки через `pg_stat_activity`, затем завершает первую и проверяет результат второй. Это независимые backend-соединения, не последовательная имитация JavaScript.

По четыре сценария на READ COMMITTED, REPEATABLE READ и SERIALIZABLE:

1. Вставка детализации 80 ₽ при бюджете 100 ₽ → конкурентное уменьшение бюджета до 50 ₽.
2. Уменьшение бюджета до 50 ₽ → конкурентная вставка детализации 80 ₽.
3. Две машины одновременно добавляют по 60 ₽ при общем бюджете 100 ₽.
4. Уменьшение бюджета до 60 ₽ → конкурентное увеличение существующей детализации с 40 до 80 ₽.

В READ COMMITTED несовместимая вторая операция отклоняется CHECK (`23514`); в проверенных гонках REPEATABLE READ/SERIALIZABLE — конфликтом сериализации (`40001`). Обе несовместимые операции не подтверждаются одновременно.

Ещё пять сценариев:

- Две допустимые детализации 40 и 50 ₽ подтверждаются, итог — 90 ₽.
- Откат первой вставки освобождает резерв: уменьшение бюджета после неё разрешено.
- Удаление детализации освобождает резерв и позволяет уменьшить бюджет до нуля.
- Транзакция REPEATABLE READ со снимком до первого счётчика не может пропустить новый резерв: попытка уменьшить бюджет получает `40001`.
- Перенос расхода между заказами: превышение откатывает обе стороны; после достаточного увеличения бюджета перенос проходит; смена на `additional` освобождает резерв.

После каждого сценария сравниваются реальный `SUM(amount)` строк `in_order`, служебный `allocated`, служебный `budget` и фактический `orders.expenses`: счётчик соответствует журналу, бюджет соответствует заказу, сумма детализаций не превышает бюджет.

UI отдельно показывает ошибку `40001`/`40P01` и сохраняет введённые поля для повторной отправки. Реальная Supabase-конфигурация и пользовательские политики других проектов не подменяются этими проверками — после запуска SQL в целевом проекте нужен smoke-тест обычными пользователями по docs/EQUIPMENT.md.
